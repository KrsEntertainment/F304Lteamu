# F304Lteam — сайт киностудии

Стриминг-платформа студии: каталог, сериалы, актёры, новости, админка.
Данные хранятся **в одном общем хранилище на сервере**, поэтому телефон, ноутбук
и планшет видят одно и то же, а правки из админки не откатываются после
перезагрузки.

## 🌐 Адрес сайта

| | Адрес | Что отдаёт |
| --- | --- | --- |
| Сайт | https://krsentertainment.github.io/F304Lteamu/ | готовый интерфейс |
| Сервер + база | `main.ts` (Deno Deploy + Deno KV) | `/api/*`, `/uploads/*`, сам сайт |

Один и тот же код `main.ts` отдаёт и сайт, и API, и загруженные файлы. Если
открыть его адрес — сайт работает полностью, без GitHub Pages.

## Как устроено сохранение

```
Телефон ──правка──► сервер (main.ts) ──► Deno KV (постоянная база)
Компьютер ──чтение──► тот же сервер ◄──┘
```

| Что | Где |
| --- | --- |
| Каталог, актёры, новости, настройки | запись `studio/meta` в Deno KV |
| «Мой список», прогресс просмотра | `list/<устройство>`, `progress/<устройство>` |
| Постеры, видео | чанки `media/*` в Deno KV, ссылка `/uploads/<файл>` |
| Локальный кеш | `localStorage` — мгновенный старт и работа без сети |

- **Никакого входа, токенов и поиска.** Писать может только свой же сайт
  (совпадение origin), поэтому правки из админки уходят в базу сами. Чужой
  сайт записать не сможет, зрителю для чтения ничего не нужно.
- **Адрес сервера — одна строка.** `SERVER_URL` в `src/utils/api.ts`
  (или `VITE_API_URL` при сборке). Пока значение пустое, используется тот же
  домен, что и у сайта.
- **Защита правок.** Изменение сразу пишется в `localStorage` и помечается
  «не отправлено». Пока метка стоит, серверная копия не перетирает локальную;
  отправка повторяется каждые 30 секунд. Индикатор внизу слева честно
  показывает: «Сохранено везде» / «Сохранение…» / «Есть неопубликованные правки».
- **Опрос** — каждые 30 секунд и при возврате на вкладку.

### Вход в админку

Тройной клик по логотипу `F304Lteam` → код `9086` (это просто ключ от панели)
→ вкладка **«Сохранение данных»** (там же статус связи и кнопка
«Отправить правки сейчас»). Вводить что-либо ещё не нужно: сохранение работает
и без входа в админку.

## Запуск сервера

```bash
npm ci && npm run build         # собрать сайт в dist/
deno run -A --unstable-kv main.ts   # сервер на http://localhost:8000
```

Переменная окружения: `PORT`. Вход и токены не используются.

### Публикация на Deno Deploy

`deno.json` уже содержит конфигурацию (`install`, `build`, `entrypoint ./main.ts`).

1. console.deno.com → **New App** → репозиторий `KrsEntertainment/F304Lteamu`.
2. **Databases → Provision Database → Deno KV** → **Assign** к приложению.
   Без этого шага сервер работает в памяти и предупреждает об этом в админке.
3. После сборки адрес вида `https://<app>.<org>.deno.net` — это и есть домен
   сайта с общей базой.

## Локальный запуск и публикация

```bash
npm install
npm run dev              # Vite с HMR (API отдельно: deno run -A --unstable-kv main.ts)
npm run build            # сборка dist/ + state.json
./scripts/publish-pages.sh   # публикация сайта и состояния в gh-pages
```

## Проверки

```bash
npm run test:smoke       # рендер без ошибок консоли
npm run test:server      # запись/чтение/перезапуск сервера (Deno KV)
npm run test:app         # админка → база → «другое устройство» на реальной сборке
```

## Структура

```
data/state.json             общая база контента и зрительских данных
main.ts                     сервер: API + сайт, хранилище Deno KV
deno.json                   конфигурация сборки и деплоя
src/
  App.tsx                   главный экран, синхронизация состояния
  components/ServerSyncPanel.tsx   статус общей базы, отправка правок
  utils/sync.ts             pull/push, опрос изменений, нормализация путей
  utils/api.ts              клиент API и адрес сервера
  utils/mediaStore.ts       медиа: сервер -> IndexedDB (офлайн)
  utils/asset.ts            пути к статике (корень домена или подпапка)
  data/initialData.ts       стартовый контент студии
scripts/                    serve, publish, тесты
public/images/              постеры и фото
```
